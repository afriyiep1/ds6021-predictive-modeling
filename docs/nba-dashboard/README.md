# Courtside — DS 6021 NBA Predictive Modeling Dashboard

An interactive GitHub Pages dashboard for the 2017–18 NBA regular season: 1,230 games, two team-game records per game (2,460 rows).

Live site, once deployed: https://afriyiep1.github.io/ds6021-predictive-modeling/nba-dashboard/

## How it works

1. **Explore Data.** Filter by NBA team, home/away and win/loss. View filtered summary cards, an interactive `FGP` versus `PTS` scatterplot, a win/loss boxplot, team win rates and variable correlations. CSV export respects the filters.
2. **Logistic Regression.** The binary target `win` is derived from `W/L`. The predictors are `MIN`, `PTS`, `FGP`, `TPP`, `FTP`, `REB`, `AST`, `STL`, `BLK`, `TOV`, `PF`, and `home_away`. `FGP`, `TPP`, and `FTP` are renamed from `FG%`, `3P%`, and `FT%`. The preprocessing pipeline includes `StandardScaler` for numeric columns and `OneHotEncoder(drop='first')` for `home_away`. Choose unpenalized, L2 or L1 logistic regression and regularization strength `C`. The models fit only the training data.
3. **Threshold experiment.** The slider covers 0.10–0.90 and changes only predicted class labels, **not** model probabilities or coefficients. Balanced accuracy, precision, recall, F1 and the confusion matrix update. Log loss and ROC AUC stay fixed for the same model and evaluation subset.
4. **Clustering.** Choose K-means (k-means++ initialization, Lloyd updates) or Ward hierarchical clustering, `K=2…7`, any **2–6** of the 11 numeric statistics, and raw versus standardized inputs. The chosen features govern distances; the first two selected features are used for the 2D scatter. The panel includes silhouette, K-means elbow/WCSS, cluster feature profiles and a 45-observation Ward dendrogram. The output labels are **descriptive profiles, not win/loss predictions**. Win/loss data is not used by either clustering algorithm.

## Reproducibility and sample sizes

- Logistic models train on **738 unique games (1,476 rows)**, validate on **246 games (492 rows)**, and test on **246 games (492 rows)**, splitting games chronologically so two team rows from a game stay together. The fitted `Pipeline` is generated by Python; saved probabilities support fast browser-side interaction.
- Clustering works on a fixed, team-balanced **240-row sample** (8 randomly selected team-games from each of 30 teams; `random_state=123`). This browser-side approach permits *arbitrary* 2–6 feature selections and a responsive Ward dendrogram on a static host. Both clustering methods use this **same** 240-row sample; silhouette is evaluated on all 240 rows. This is not a claim to have clustered all 2,460 rows.
- Important: box score stats such as `PTS` are available only **after** a game. The fitted classifier characterizes the results of completed games; it does **not** forecast future matchups. We intentionally exclude `+/-`, which directly indicates the winner.

## Build locally

```bash
python -m pip install -r requirements.txt
python build_dashboard.py
```

The Python script reads `nba.csv`, fits `scikit-learn` pipelines, and injects data into `template.html` to generate `index.html`. The HTML uses Plotly.js from the [official versioned CDN](https://cdn.plot.ly/) so it can run from GitHub Pages without Dash or a Python backend. An internet connection is required to load Plotly.js. No external services receive the NBA dataset.

## Publish

This course website is served from the repository's `main` branch `/docs` folder. Put the generated `index.html` at `docs/nba-dashboard/index.html`. Put the supporting source files in that same folder if students need to reproduce the build. Commit to `main`; GitHub Pages will then serve the path shown at the top. The interactive page doesn't depend on running Python in the browser.

## Teaching notes

Discuss the difference between *ranking probabilities* (ROC AUC) and *classifying at a threshold*, between log loss and 0/1 classification accuracy, and between supervised win/loss prediction and unsupervised descriptions of playing styles. Also note that `home_away` is encoded using a single indicator with **Away** as the reference level, so the coefficient is a Home-versus-Away contrast; all numeric coefficients are expressed per one training-set standard deviation.
